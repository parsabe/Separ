# v2.2 evaluation

v2.2 was measured on variant seed **255158241**, drawn with `secrets.randbelow(900_000_000) +
100_000_000` and recorded in docs/variant-seeds.md before any v2.2 code was written. The variants
were generated once (`scripts/generate_variants.py`, 940 variants) and replayed in v2.1 (the tip of
tag `v2.1`) and in v2.2 (`scripts/dump_matrix.py`), then compared
(`scripts/compare_versions.py`). **The weights are unchanged**: every v2.2 signal reuses an
approved weight (owner decision, 2026-11-03).

v2.1 cannot replay the 15 variants of the new scenarios S57–S61: it knows neither the event type
`auth` nor the identity roles. The comparison covers the 925 variants both versions can replay.

Per-variant data: `docs/evaluation/v2.1-seed-255158241.jsonl` (925) and `v2.2-seed-255158241.jsonl`
(940). Comparison: `docs/evaluation/comparison-seed-255158241.md`.

## Changes (design-decisions.md A73 to A77)

- **A73, sensor ingest.** Admin mapping files and `refmon serve --ingest`, with templates for
  Tetragon, Falco, sshd, Keycloak, Shibboleth, M365 and Postfix/Dovecot. The core is not changed.
- **A74, identity events.** `auth`, `mail_rule` and `oauth_grant`, with a per-account baseline.
  The signals reuse approved weights: `contract_surprisal`, `effect_credential`, `effect_exfil`
  and `effect_persist`.
- **A75, the login cap.** A login story is held at most; the verdict records `identity_cap`.
  Networks seen during an incident are parked.
- **A76, decoy accounts.** Canary class `account`. Login sources are checked against the threat
  lists.
- **A77, observe first.** The reused rules are in observe mode for the identity roles only.

## The new scenarios (v2.2 only)

| scenario | kind | variants | decision | what the Gate does |
|---|---|---:|---|---|
| S57 MFA push fatigue, then a login from a new network | malicious | 3 | 3 hold (login cap) | nothing yet: observe mode (A77) |
| S58 stolen password from a new network, then forwarding outside | malicious | 3 | 3 hold (login cap) | nothing yet: observe mode |
| S59 password spraying reaches a decoy account | malicious | 3 | 3 block (canary) | ends the decoy account's session |
| S60 a month of ordinary logins | benign | 3 | 3 allow | |
| S61 mistyped passwords, then a usual login | benign | 3 | 3 allow | |

In the matrix's terms, 3 of the 9 malicious variants are contained (the S59 blocks). The 6 S57/S58
holds pause nothing, **on purpose**: those rules are in observe mode until a pilot. Switched to
block, the same hold pauses the account's session (`tests/test_identity.py`). The timing variants,
with minutes or more than a story window between the steps, still hold, because the per-account
baseline carries across stories.

## What this evaluation does not cover

- **Robustness of login stories.** The generator's six dimensions (delivery, entry, obfuscation,
  timing, destination, lineage) were made for process attacks. Only timing applies to a login
  stream, so S57–S61 get 3 variants each: a regression check, not a robustness measure. Dimensions
  of their own (spacing of failures, number of usual logins, networks shared between users) are
  future work for the generator.
- **False holds of real users.** A traveller's first login from a new network is held once the
  account is mature. How often that happens is what the observe-mode pilot is for.
- **The templates against real output.** They were tested on synthetic samples shaped like each
  system's documented format only; `refmon ingest check` is the admins' step.
- The active seed of `make reproduce` is now v2.3's (837115701); this seed is retired.
