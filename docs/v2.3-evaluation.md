# v2.3 evaluation

v2.3 was measured on variant seed **837115701**, recorded in docs/variant-seeds.md before any v2.3
code. The variants were generated once (1025) and replayed in v2.2 (tag `v2.2`) and in v2.3 (tag `v2.3`). **No rule and no weight changed**: v2.3 adds policy
vocabulary (roles, contracts, destinations, protected assets, executable classes) and mapping
templates only (A78, A79).

v2.2 knows the new roles but has no policy entries for them, and the new scenarios S62–S66 are
v2.3's. The comparison covers the 933 variants of the scenarios both versions share; the new
scenarios' 92 variants are reported for v2.3 alone. Data: `docs/evaluation/v2.2-seed-837115701.jsonl`
(933), `v2.3-seed-837115701.jsonl` (1025), `comparison-seed-837115701.md`.

## The new scenarios (v2.3 only)

| scenario | kind | variants | outcome |
|---|---|---:|---|
| S62 privileged host-mounting pod + cluster role binding (Kubernetes audit) | malicious | 3 | 3 block |
| S63 web container reads its service-account token, calls the API server and cloud metadata | malicious | 9 | 9 block |
| S64 untrusted Terraform module runs a local-exec that fetches code | malicious | 31 | 24 block, 7 effective hold |
| S65 an admin debugs a pod and reads a secret | benign | 22 | neutral 14: 5 allow, 9 hold (F14); labelled 8: 6 hold, 2 block |
| S66 terraform apply | benign | 27 | neutral 11: 11 allow; labelled 16: 11 hold, 5 block |

Malicious variants of the new scenarios contained: **43 of 43** (100 %, Wilson [91.8, 100]).

**F14 (a generator labelling finding).** Every one of S65's 9 neutral holds has the `entry`
mutation, which replaces the admin with a launcher, a shell, a script host or a scheduler. Those
roles may not read Kubernetes secrets, so for the mutated story the hold is correct. The
generator's labelling table (docs/variant-seeds.md) does not know that the role itself is what
makes S65 benign, so it calls the mutation neutral. Changing the labelling would change the
measurement, so it is recorded here, not fixed.

**F13 (a specification finding).** A persist has no role allowance: a CI service account that
creates a DaemonSet or a CronJob raises `effect_persist` alone, which is a hold
(`tests/test_ingest.py`). The answer within the rules is a scoped, expiring policy exception for
`R-EFF-PERSIST` and the CI role (docs/admin-integration.md).

## Not covered

- The templates were run on synthetic samples shaped like each format, not on a real cluster.
- One container escape is not seen: a process that leaves its container without an API call or a
  privileged pod (a kernel exploit) is seen only by what it does next on the host.
- Robustness of API-client stories has the same limit as login stories: the generator's
  dimensions apply only partly.
- 837115701 is the active seed of `make reproduce` (tags `v2.2` and `v2.3`).
